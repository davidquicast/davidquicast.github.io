# Shared editorial text composition

The site is generated by Jekyll. Titles and excerpts remain real server-rendered HTML; there is no React runtime or hydration step. A shared enhancement uses [`@chenglou/pretext`](https://github.com/chenglou/pretext), pinned at **1.0.0** under its MIT license. The browser bundle is generated with esbuild 0.28.2 and links to the complete dependency license and third-party notices copied to `assets/js/dist/editorial.LICENSE.txt`. The minified ES2022 bundle must bypass Jekyll's legacy JavaScript minifier.

## Integration

Load `assets/css/editorial.css` and `assets/js/dist/editorial.js` with a module script. Add `data-pretext` to a plain-text heading or excerpt, or to the anchor inside a heading:

```html
<h1 data-pretext="lines">Building practical AI systems.</h1>
<h2><a href="/projects/example/" data-pretext>Project title</a></h2>
<p data-pretext>An editorial excerpt.</p>
```

`data-pretext="lines"` renders the computed lines in individual spans for the finite identity entrance. Those precomposed spans use `white-space: nowrap` to prevent a second browser wrapping pass when Canvas and DOM glyph advances differ slightly. A long unbroken token that cannot be materialized without changing the original text keeps native word wrapping instead. The default mode searches for the narrowest text width retaining the original line count, then lets the browser paint selectable text at that balanced width. Both modes use the same cached preparation. The identity line animation is finite and disabled by `prefers-reduced-motion`. No content is hidden until an observer runs.

The opt-in belongs on the element containing plain text, including an anchor when a title is linked. Elements with existing child markup are intentionally left alone: controls, mixed-weight paragraphs, code, and rich article content retain native HTML layout. The layer never replaces a link or creates an accessibility-only duplicate. If a long token cannot be materialized without changing the original text, line mode falls back to native wrapping at the calculated width.

## Measurement lifecycle

1. Wait for `document.fonts.ready`, then derive canvas font shorthand, letter spacing, line height, and available content width from each target's computed CSS.
2. Call `prepareWithSegments(text, font, { letterSpacing, wordBreak })` once per text/font/options signature. The locale is set from `<html lang>` with `setLocale()`.
3. Use cached preparation for repeated `layout()` calls during the width search, then `layoutWithLines()` once for the selected width.
4. `ResizeObserver` and a batched animation frame recalculate the width, reading all computed styles and column widths before writing any new composition. Resizing does **not** repeat preparation unless responsive font sizing changes the font signature.
5. A mutation observer re-prepares changed text, including edits made while a parent is hidden. Ancestor class/style changes are batched so inherited font changes are measured even when the column width stays constant; color-only changes reuse the previous composition without numeric layout work. `document.fonts.loadingdone` invalidates old font measurements. New dynamically inserted targets can dispatch `portfolio:content-updated`, or call `window.portfolioPretext.refresh()`. The insertion event can be dispatched on either `document` or `window`.

Each enhanced element exposes `data-pretext-ready`, `data-pretext-lines`, `data-pretext-width`, `--pretext-lines` and `--pretext-height`. These values reflect actual library results. `window.portfolioPretext.snapshot()` exposes preparation/layout counts and per-element geometry for read-only inspection. `refresh()` is an explicit integration hook, not a requirement for ordinary browser resizing.

## Where it is used

The shared selectors support the profile sidebar, filtered catalog project/article/paper titles and excerpts, project directory/detail headings, article titles and editorial introductions. The catalog controller assigns each card its new width before refreshing composition, then reads the resulting heights for masonry placement. ResizeObserver catches later font, image and content changes without re-preparing unchanged text. Consult the templates' `data-pretext` attributes for the exact live set. Body paragraphs and controls use the browser's normal text layout.

## Fallback and limits

Source HTML is readable, indexable and linked with JavaScript disabled. A measurement error retains the current text and clears calculated geometry. Failed metric signatures are cached so privacy restrictions or unavailable Canvas contexts do not create retry loops; genuine text/font/width changes or an explicit refresh can recover. Browser text selection and accessibility read the same text users see. The current design uses English Latin font subsets; the multilingual infrastructure remains available but hidden. Mixed inline typography is deliberately excluded rather than approximated with a plain font measurement. There is no text clamping or content truncation. If rich inline markup replaces an enhanced plain-text target, its markup and links remain intact, the obsolete prepared handle is removed, and `data-pretext-ready="native"` explicitly identifies native layout without stale line diagnostics. Selection character offsets survive rebuilding the animated line spans after a resize.

## Build and verification

Run inside Docker:

```sh
npm ci
npm run build
npm run test:pretext
```

`npm run watch` rebuilds the browser bundle as the source changes. The browser tests use system Chromium through Playwright. At 320, 390, 768 and 1440 px, tests compare the library's line count and predicted height with independent DOM character Range line boxes. Other tests check 200% text-size updates, preparation reuse on resize, dynamic content updates, intact links and no-JavaScript content, and reduced motion. These exercise genuine browser measurements rather than mocking the library.

The current portfolio loads self-hosted Inter Latin WOFF2 weights 400, 500, 600 and 700 as needed. Its OFL license remains in `assets/fonts/editorial`. DM Sans and Zilla Slab assets are retained for font-loading regression fixtures and are not requested by current page layouts.

## Live integration checks

With the Docker Jekyll server running, execute:

```sh
PORTFOLIO_URL=http://127.0.0.1:8080 npm run test:portfolio
```

The integration suite checks the homepage, work directory, journal, and real linked project and article pages at the same four responsive widths. It compares real text line boxes to Pretext results and checks horizontal overflow. It also exercises keyboard navigation and overlay focus restoration, persisted theme preference, no-JavaScript navigation, filter/search/year combinations and URL restoration, zero-result recovery with focus restoration, scoped article readers and native masonry transitions, native search and image viewer, article table of contents, and code copying. Axe checks cover the main surfaces in both themes at 320 and 390 px; visual inspection remains a separate review.

An additional regression doubles every computed text size on real pages at both 320 and 390 px, checks that the H1 actually doubled, and checks that the document remains within the viewport. This catches problems that changing the root font size would miss when individual sizes use px.

The suite blocks only the development live-reload client so rebuild notifications cannot interrupt browser navigation. It uses the same generated content and runtime assets as the running app. Tests are not included in the published site.

## Resilience checks

`tests/editorial-edge.spec.js` adds regression coverage for inherited and late-loading fonts, hidden-text edits followed by reveal at unchanged width, rich inline replacement, both insertion event targets, selection across responsive line recomposition, cache stability for changes that do not alter text metrics, and unavailable Canvas fallback without repeated retries, followed by recovery through resize or refresh. Its live checks block the deferred application script, block browser storage, and disable JavaScript completely. Essential navigation and theme controls are handled by the small inline bootstrap independently of the downloaded application script. Optional search, filter and project deck controls are disabled in server HTML and enabled only after their handlers are installed.

## Current profile and overlay composition

The shared profile sidebar, project/blog/research card titles and excerpts, About heading, project details and article headings use the same prepared-text layer. Native catalog layout sets the available card width before calculating its actual height. Preparation is reused when only width changes; sources, fonts and spacing invalidate the relevant preparation.

Fetched readers dispatch scoped mount and unmount events. New elements are registered through `portfolio:content-updated`; mounting does not globally refresh or invalidate the background preparation cache. Unmount explicitly discards each removed scope’s records, observers and scheduled work. Repeated reader use therefore leaves the original profile targets registered and releases article-only targets.

About’s paragraph pagination uses native DOM ranges to preserve rich biography links and semantics. Pretext remains responsible for its heading, while the browser measures the available paragraph area. Normal controls, full body paragraphs and extracted CV text do not receive artificial text measurement. The CV pages are generated from the original PDF as described in the [CV pipeline](cv.md).

`tests/profile-shell.spec.js` covers the actual default catalog, real overlay URL/reload/history behavior, About viewport pagination and CV nesting. Dynamic lifecycle fixtures verify resource disposal. Captures, frame timing diagnostics and full verification counts are recorded in [current verification](design/section-refinement.md).

Research cards and archive headings, static paper titles and paper overviews use the same shared layer. Full author lists, citation code, attribution notes and profile controls retain native HTML text. New paper readers participate in the existing scoped registration/disposal lifecycle.

Category composition shares CSS column tokens with the existing native feed controller: four desktop project columns, three blog columns and single Research rows. Width changes reuse prepared text and trigger actual line layout for titles and summaries, including the phone row's wider summary measure. About's authored sections, rich paragraphs and native column pagination remain outside unnecessary Pretext measurement; its heading continues to use the shared layer.
