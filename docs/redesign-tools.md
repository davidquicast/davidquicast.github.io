## Component decisions and attribution

The official shadcn registry was searched before composing navigation, project/blog filters and empty states. `navigation-menu`, `toggle-group` and `empty` implementations were retrieved through `shadcn view`, including actual source content; component documentation and example/API URLs were fetched. Their dependencies were reviewed: React, Radix/Base UI, class variance utilities and icons. Those implementations are incompatible with the site's Liquid runtime without adding React. The design therefore adapts their composition and state conventions into semantic native controls: real navigation links, a labelled menu button with expanded state, pressed filter choices, and an empty state containing a useful recovery action. No React source or dependency is shipped.

shadcn/ui is MIT, Copyright (c) 2023 shadcn. The source snapshot and full MIT licence remain in private tool artifacts. No 21st component was retrieved; no claim is made that 21st supplied design references or code.

## Development environment

Docker Engine 29.8.0 was verified on ARM64. The project image pins Ruby 3.4.11 and Node 24.22.1; npm resolves through the existing lockfile. The final rebuilt image installs Chromium 156.0.8078.79 for browser checks; the final performance traces used 156.0.8078.47. Poppler 22.12.0 and ImageMagick 6.9.11-60 generate deterministic previews from the original CV PDF, without a client rendering library; see [CV pipeline](cv.md). Optional tools use MCP SDK 1.32.2 and Playwright 1.64.1. Native gems needed an ARM64/Ruby-compatible resolution; `observer` is explicit because citeproc-ruby requires this library, removed from the Ruby 3.4 default set. The lockfile is preserved and never deleted by the startup script.

`docker compose up --build` starts the site at `http://localhost:8080` with live reload. Draft preview is enabled only in development through `JEKYLL_PREVIEW_DRAFTS=true`; production builds must omit `--unpublished`, `--drafts` and `--future`. No backend is added. The entrypoint signals only its own child processes, watches configuration changes, and runs the frontend watcher when configured.

Optional tool audit (2026-11-04): the fresh audit initially reported six affected dependency nodes, including four moderate findings propagated from minimatch. A scoped override for `@ts-morph/common@0.27.0` selects `minimatch@11.0.1`, the fixed version in the [maintainer advisory](https://github.com/isaacs/minimatch/security/advisories/GHSA-g3hv-75wg-m249). Its [documented CommonJS/named API](https://github.com/isaacs/minimatch/tree/v11.0.1#usage) and Node engine remain compatible with the consumer's two `minimatch(path, pattern)` calls. Version 11 changes the matching engine internally, so the override is restricted to that reviewed consumer rather than applied globally.

After a clean `npm ci`, eight representative path/glob cases and actual ts-morph Project filtering passed. shadcn MCP discovery, registry search, component metadata, a real `toggle-group-demo` source example and the audit checklist were re-exercised successfully. The lockfile changes only minimatch plus its new matcher dependency; shadcn remains 4.23.0. The new audit reports **three low findings and zero moderate/high/critical findings** in this separate tool installation. The remaining [deepmerge advisory](https://github.com/advisories/GHSA-gcqx-w48m-w2h4) propagates through the shadcn registry chain; the suggested incompatible shadcn downgrade was not applied. These packages remain excluded from the published site and its runtime bundle.

Verification environment result: Docker Compose was built from scratch on ARM64 and reached healthy status with host ports 8080 and 35729. Node build/watch and Jekyll live reload run together; duplicate direct Jekyll processes were stopped to keep one writer for `_site`. The first cold local Chromium MCP trace observed LCP 538 ms and CLS 0.00 at 1440 px, unthrottled CPU/network on localhost. These are development lab observations, not production or field measurements. Browser console reported no warnings/errors for that navigation.

## Initial verification (2026-10-28) and deliberate exceptions

These measurements describe the first delivery. The [current read.cv verification](design/research-integration.md) supersedes these historical measurements.

The final production build completed in 5.844 seconds in the non-root Docker service. Official Chrome DevTools MCP cold-navigation traces on that build, with **4x CPU slowdown and Fast 4G emulation**, observed desktop LCP **1687 ms / CLS 0.00**, and mobile 390 px LCP **1232 ms / CLS 0.00**. These are single local lab observations, not real-user field statistics or a performance guarantee. Both traces had no console warnings/errors, failed network requests or external requests. A previous mobile shift of 0.14 was traced to late JavaScript collapsing the mobile navigation; setting the enhanced header state before first paint removed that shift in the repeated measurement.

Visual inspection covered home, project detail, blog and article in desktop 1440 px, tablet 768 px, mobile 390 px, narrow 320 px and landscape 844 by 390 px. All lazy images were scrolled into view before captures; horizontal overflow, broken images, JavaScript errors and HTTP errors were absent in these checks. Computed font sizes were also doubled on all text elements at 390 px (home H1 58 to 116 px, project/blog 42 to 84 px, article 36 to 72 px); all four pages retained a 390 px document width. Captures were opened, including complete desktop/mobile pages.

Two taste inspection rounds ran against the implementation, the second against production. Real line-wrap, contrast and date-position findings were corrected. The remaining eyebrow finding is a false positive: the inspector interprets the working **Explore my work** primary action above the next section as a decorative label. The action is retained. Other warnings are recorded rather than represented as passing: the measured third family is semantic code monospace; the cream warning describes light footer text; responsive component scales create more measured sizes than the house recommendation; no authentic video was available or needed, while native typography and scroll interactions provide visible motion. The name-only H1 warning overlooks the visible profession sentence immediately alongside it.

The design-audit script was run against the changed CSS/JavaScript surface. Its active checks found no layout-property animations, lost focus outlines, missing reduced-motion guard, excessive will-change or unsupported motion loops. JSX/component checks and Liquid markup checks are **not applicable to that script**, so semantic markup was reviewed separately using the fresh Vercel rules and actual browser checks.

The final development service runs as `portfolio` with UID/GID 1000 by default; optional `PORTFOLIO_UID` and `PORTFOLIO_GID` build arguments support other Linux hosts and CI runners. Build and dependency caches belong to that user. Jekyll disk caching is disabled in development to avoid shared-cache ownership races. Compose uses `restart: unless-stopped`; no extra unbounded application retry loop is added. A real temporary source edit was observed through Jekyll regeneration, a LiveReload WebSocket and an automatic browser reload; deletion then returned 404. The probe source was removed. VS Code Dev Containers uses the same Compose service and starts no duplicate Jekyll process.

Codex project configuration is also provided in `.codex/config.toml`, matching the Docker commands in `.mcp.json`; the 21st entry stays disabled. [Official Codex MCP configuration](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) uses trusted project TOML. Native client discovery requires a client reload and has not been observed in this already-running session. Chrome DevTools uses an explicit `/srv/jekyll` filesystem root so host-side client roots do not prevent saving artifacts inside the Docker workspace.
